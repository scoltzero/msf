# Mihomo 测速 URL 与 Provider 配置保留规则

更新日期：2026-10-22。对应问题：[Issue #22](https://github.com/scoltzero/msf/issues/22)。

## 问题与修复范围

原实现将有效 YAML 中的 Provider 压缩成“名称、订阅地址、是否存在手动节点”，随后重新生成整个 `proxy-providers` 块。启动恢复、向导同步和配置重新生成可能因此丢失 `health-check.url`、`enable: false`、周期、路径、过滤器、扩展字段及普通 file/inline Provider。已应用的自定义配置源文件也会被同步覆盖。

修复后，以有效配置中的完整 Provider 定义为基础，默认值仅用于新建 Provider：

- 启动先读取有效配置，再执行网络兼容性修复和资源补齐；启动同步不删除已有 Provider。
- 向导同名订阅仅在地址明确发生变更时更新订阅 `url`，保留测速、路径和其他字段。
- 删除订阅时对照变更前的向导快照，只移除仍与原 HTTP 订阅匹配的条目；普通 file/inline Provider 和已自行修改地址的条目保留。
- `msf_manual` 是 MSF 管理的保留名称，明确清空手动节点时可以移除该引用。
- 只同步活动配置和已应用的自定义配置，不遍历修改未应用的用户配置。

历史上已经被旧版本覆盖丢失的字段不能自动推断恢复；可以从配置历史备份中找回后重新保存。本次修复保证后续同步保留这些设置。

## 页面测速优先级

从某个代理组发起节点测速时，依次选择：

1. 此次操作临时指定的 URL（若调用方提供，只作用于本次请求）。
2. 当前路径中最近一个明确“单独设置”的代理组 URL。
3. 已开启的全局覆盖 URL。
4. 节点所属 Provider 的 `health-check.url`。
5. 代理页面兜底 URL。
6. 程序内置默认 URL。

Provider 页面或 Provider 健康检查没有所属代理组的上下文，因此不套用组覆盖。混合 Provider 分组按节点选择自己的 Provider URL，不以第一个 Provider 代表全组。同一物理节点使用相同 URL 和超时的测试可以合并；使用不同 URL 或超时的测试必须分别执行。

“兜底”仅表示没有配置时补缺。测速失败直接报告，不静默换 URL。全局覆盖只改网址，不强制开启健康检查，也不改周期、lazy、timeout 等字段；页面超时设置仍是没有更具体配置时的兜底。

如果原配置额外指定了 `expected-status`，该条件也会保留；更换网址时应确保新服务的响应状态符合该条件。

## 页面设置与原始配置

在“代理页面设置 → 更多设置 → 测速设置”中配置：

- 默认测速 URL（仅兜底）。
- 全局覆盖开关及 URL。
- 点击“应用测速设置”提交网址及覆盖开关；输入过程中不反复重启内核。

这些设置按实例保存。现有 v3 页面设置仍可读取，旧设置默认关闭全局覆盖。旧客户端只保存外观、未提供覆盖字段时，保留实例已有的覆盖配置。

页面设置继续使用 `GET/PUT /api/v1/settings/proxy-page`。`delayTestUrl` 表示兜底，新增的 `delayTestOverrideEnabled` 和 `delayTestOverrideUrl` 分别保存覆盖开关和网址。默认分组的专用写入接口是 `PUT /api/v1/mihomo/proxy-groups/{name}/test-policy`，请求仅接受 `mode`（`inherit` 或 `override`）与 `url`，只允许管理员调用。

`configs/mihomo/config.yaml` 与已应用的 `user_configs/*.yaml` 保存基础配置。启动 Mihomo 前，MSF 从基础配置和已保存的页面设置生成 `configs/mihomo/msf_runtime.yaml`，内核通过 `-f` 读取该运行副本。该文件是派生产物，不应手动编辑。

例如 Provider 原网址为 A，全局覆盖为 B：开启时运行副本使用 B；重启后仍使用 B；关闭后重新从基础配置生成 A。整个过程不把 B 回写到 Provider 原始定义。修改原始配置、重新应用用户配置和内核自动重启都会在下次启动时重新计算运行副本。

只有会改变实际 URL 策略的设置更新才需要重启运行中的 Mihomo；单纯调整外观不重启。应用后探测控制器；启动或探测失败时恢复旧设置，再按旧策略启动。内核原本未运行时只保存设置，下次启动应用。

## 代理组继承与兼容

组编辑器提供“继承全局规则”和“此策略组单独设置”。选择继承时保留组的原始 URL，但它不再占据页面测速的最高优先级。选择单独设置时必须提供有效 HTTP(S) URL。

默认生成配置也可以通过组上的编辑按钮或“策略组管理 → 测速设置”调整这两个字段；分组类型、成员、路由及其他配置继续只读。专用接口只接受 `mode` 和 `url`，不切换配置模式；这类测速例外会在普通配置重新生成时保留。自定义配置仍可使用完整组编辑器。

原始 YAML 使用 `x-msf-test-url-mode: inherit` 或 `override` 明确保存此状态，运行副本会去除组内的 MSF 编辑元数据。直接编辑 YAML 同样可以设置该字段。

没有这个字段的旧配置按如下方式解释：

- 已知生成模板中的同名组及原模板 URL 视为继承，避免内置默认值使全局覆盖失效。
- 自定义/导入配置中已有的组 URL 视为明确设置，保留用户配置的含义。需要全局覆盖接管时，在组编辑器中切换为继承。
- 没有组 URL 时视为继承。新生成模板在测速组锚点中显式标记继承。

## 后台自动测速的内核边界

Provider 定时健康检查使用“全局覆盖 → Provider 原始 URL → 兜底”。不同代理组的例外不会反向修改整个 Provider。

Mihomo 的 url-test、fallback、load-balance、smart 自动组各自只能配置一个 URL。单组明确设置时使用自己的 URL；继承且开启全局覆盖时使用全局 URL；没有全局覆盖时保留该组原有后台 URL，缺失时补页面兜底。这是组自动选路的共同测试基准，不能让同一个原生自动组按不同 Provider 同时使用多个基准。

页面对混合 Provider 分组的手动测试可以逐节点使用不同 URL，因此“继承且关闭全局覆盖”的页面测试与内核原生组自动选路可能采用不同网址；Provider 后台健康检查仍各自保留原网址。需要统一比较基准时，应为该组单独指定 URL，或开启全局覆盖。MSF 不通过改写 Provider 原网址或停用自动选路来掩盖这一差别。

## 测速结果

页面手动测速样本保存实际 URL。不同网址的样本分别保留，组内优先显示当前有效 URL 的样本；只有其他 URL 的旧样本时提示重新测速，不将其显示为当前规则的延迟。内核返回但未标注 URL 的记录仍可显示，提示中说明其网址未知。测速按钮提示可查看已记录的实际网址。
